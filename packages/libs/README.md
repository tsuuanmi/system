# @tsuuanmi/system-libs

Pure libraries shared by `system` plugins. These are **not plugins**: each has
exactly one correct answer per process
([plugin model](../../docs/architecture/plugin-model.md#what-is-not-a-plugin)).

| Export | Purpose |
|---|---|
| `canonicalJson`, `contentId`, `sha256` | canonical JSON and `sha256:` content addresses ([reference](../../docs/reference/schemas.md#artifact-envelope)) |
| `accountSettings`, `ASSIGNED`, `pooledTermsDecision`, `AccountSetting`, `AccountMode`, `PooledTerms`, `ProviderAccounts` | how each provider's accounts are used ([ADR-0052](../../docs/decisions/adr/0052-accounts-are-assigned-unless-pooling-is-recorded.md)): `assigned` (the default) or `pooled`, only with whole `pooledTerms` (who confirmed, when, which terms). `accountSettings` checks a source's `providers` entries and refuses a bad one, naming its place; `pooledTermsDecision` is the `gate` decision a source records for a pooled provider at start. Shared by the website and agent Worker sources |
| `renderBrief`, `startPrompt`, `bodyText`, `Brief`, `BriefError`, `NO_LOCAL_SANDBOX`, `BRIEF_LIMITS`, `BRIEF_FILE_PATH`, `questionsOf`, `QUESTION_LIMITS` | briefs (`brief@1.x`): the default text rendering a Worker source sends as its prompt, each pointer replaced by its artifact's text (`bodyText`: the body's `text`, else its canonical JSON, which a digest's quote check reads too); `startPrompt` takes a start's prompt or renders its brief, at the requirement's classification ([briefs](../../docs/design/workflow-engine.md#briefs)). `BRIEF_FILE_PATH` is where a brief's files (`files`, 1.2) may go: one named file under `.system/`. A brief with `ask` (1.2) tells the Worker how to answer with questions instead, and `questionsOf` reads them: an answer that is wholly one `{"questions": [...]}` object, 1 to 8 of at most 500 characters, else none ([a question from a run](../../docs/design/workflow-engine.md#a-question-from-a-run)) |
| `lessonsSection`, `lessonsSectionOf`, `lessonApplies`, `appliesOf`, `pathMatches`, `lessonsText`, `LESSONS_PATH`, `LESSONS_LIMITS`, `LESSONS_HEADING`, `LessonsFor` | a repository's lessons (T220; layer 5 of the [handbook](../../docs/design/handbook.md)): the bounded section a Worker's brief carries of the lessons that apply to its role and touched paths (a lesson's `Applies:` clause; none: `develop` and `review`), at most 30 lessons and 12,400 UTF-8 bytes. Pure, the one implementation: the agent Worker source renders it from the file committed at its repository's HEAD, and the workflow engine measures it against the handbook's bound |
| `SchemaRegistry`, `SchemaError`, `extractJson` | validate records against [`schemas/`](../../schemas/README.md) by tag (ADR-0014), or a value against one of a schema's `$defs` (`assertDef`, an MCP tool's input or output); the schema files are loaded once per process and each validator compiled once, shared by every registry, so a registry costs nothing to make; `extractJson` reads the JSON object a model's answer ends with (untrusted text: its last fenced block that holds JSON decides) |
| `captureGitSubject`, `subjectId`, `GitSubject` | the exact subject of a git working tree: HEAD plus a hash of every change on top, with the verbatim diff (REQ-WF-5). None only when git answers that the directory is gone, not a repository, or has no commit; any other failure of git throws, so a subject that cannot be read is never taken for none. A confined, read-only probe, not a command runner: fixed `git` argument lists, no shell, no hooks, no external diff or text conversion, no optional index writes, and bounded time and output |
| `snapshotRepository`, `selectFiles`, `SnapshotError`, `GIT_FLOOR`, `pinnedTo`, `isPrivateAddress`, `globMatches`, `globProblem`, `GLOB_BUDGET` | the files of a public repository at one pinned commit, for a team review: only the chosen blobs are read, in a fixed order within file and byte bounds, and every other file is listed as unread, with why ([sources](../../docs/design/teams.md#sources)). The same kind of confined probe as subjects, over https to an allowed public host only, with git pinned to every address checked (`GIT_FLOOR`: git 2.37, else it fails closed; [controls](../../docs/security/threat-model.md#threats-and-controls)); `isPrivateAddress` names an address that is not on the public internet, and `globMatches` matches a focus glob without backtracking, bounded over a whole tree by `GLOB_BUDGET` steps; it is System's one glob matcher (its `exact` mode reads the risk-tier path map, the lessons' `Applies:` paths, and a setup's generated files), and `globProblem` its one pattern validator. It takes no test seam; this package's own tests use `snapshotWithTestSeams` from source, which no other source may name |
| `dshHome`, `ensurePrivateDir`, `readOrCreateSecretFile`, `writeFileDurable`, `fsyncDir` | the harness home by DSH's own rule (`resolveDshHome`), and secret-file hygiene: `0700` dirs, `0600` regular single-link files, `O_NOFOLLOW`; `writeFileDurable` replaces a file so it survives a crash (exclusive temporary file, fsync, rename, fsync of the directory) |
| `registerSecretPath`, `secretPaths` | the process's secret paths outside the always-hidden places: the plugin that owns one registers it for as long as it exists, and agent Workers never read a registered path ([ADR-0024](../../docs/decisions/adr/0024-agent-workers-confined-for-reads.md)) |
| `USAGE_UNKNOWN_EVENT`, `UsageUnknown`, `UsageUnknownKind`, `USAGE_UNKNOWN_KINDS`, `usageUnknown`, `usageUnknownOf`, `MAX_UNKNOWN_REASON`, `reconciledBy`, `countUnknownUsage`, `UnknownUsageSources`, `UnknownUsageCount`, `UnknownRun`, `NAMED_UNKNOWN_RUNS`, `unknownUsageOf`, `ScopeUnknownSources`, `UnknownEntries`, `MAX_UNKNOWN_ENTRIES` | usage the resource ledger could not count ([resources](../../docs/design/resources.md#usage-the-ledger-cannot-count)): the `usage.unknown` event type, its data as a `usage-unknown@1.0` record (`@1.1` when it names the `partial` record of a lower bound the ledger counted), built with its reason cut to its bound and validated (`usageUnknown`, which throws on an invalid one), and read back only when valid (`usageUnknownOf`); `reconciledBy`, whether a counted record reconciles a fact (never its own `partial` one); `countUnknownUsage`, per configured pool the runs in its current window (its longest) whose usage is unknown and not reconciled, by kind, and the latest `NAMED_UNKNOWN_RUNS` (3) with their Worker, kind, reason, and whether a lower bound was counted, with the entries no pool counts; and `unknownUsageOf`, the unreconciled runs of a task or project in given pools, which a cap of that scope cannot count (ADR-0065). Each reads at most `MAX_UNKNOWN_ENTRIES` (10,000) a page at a time and says when more were there. Shared by the Worker sources that record such a unit and the surfaces and ledger that read it (the report, health, the roster, the resources ledger) |
| `QUOTA_DRAW_EVENT`, `QuotaDraw`, `quotaDraw`, `quotaDrawOf`, `drawEntries`, `DrawEntry`, `DrawReading`, `DrawState`, `DRAW_STATES`, `MAX_DRAW_WINDOWS`, `drawFigures`, `DrawFigure`, `drawFigureText` | quota drawn per run ([resources](../../docs/design/resources.md#quota-drawn-per-run), PROP-0015 E2): `drawEntries` turns each window's last reading before a run and first after it into an entry, a draw in percentage points only when both give a used share in the same window epoch (the later of `resetsAt` and `cooldownUntil`, as `accountQuotaOf` reads it), else `reset-crossing` (epochs differ, no reset named, the share went down) or `no-reading`, and `confounded` when another run on the account overlapped; never negative, never estimated. `quotaDraw` validates the `quota-draw@1.0` record, `quotaDrawOf` reads a `quota.draw` event's data back only when valid, and `drawFigures` gives per kind and window (or per kind, template step, and window) the clean draws counted, their median and 90th percentile (nearest rank), and the entries left out by state. Shared by the agent Worker source that records draws and the surfaces that show them (`system usage`, the report) |
| `livenessOf`, `LIVENESS_RULE`, `LIVENESS_VERDICTS`, `probeProcess`, `processIdentity`, `processIdentityOf`, `currentProcess`, `hostOf` | the liveness verdict ([liveness verdict](../../docs/design/scheduling-and-leases.md#liveness-verdict), ADR-0056): a pure rule pinned as `liveness@1` (`alive`, `stalled`, `unknown`, `dead`; only `dead` is death) over a run's holder, its agent process, and its latest activity, with two bounds; the process probes beside it read this host's `/proc` and say `gone` only on positive evidence (no such pid, a reused pid, an exited process, another boot), `unknown` for anything they cannot read or a process on another host |
| `quotaScoreOf`, `QUOTA_SCORE`, `accountQuotaOf`, `headroomOrderOf`, `headroomKeysOf`, `compareHeadroom`, `HEADROOM_KEYS`, `headroomLine`, `headroomReason`, `QuotaSettings`, `QUOTA_DEFAULTS`, `QUOTA_RANGES`, `quotaSettingsProblems`, `windowName` | the quota score ([routing](../../docs/design/routing.md#quota-in-every-route), ADR-0064): a pure rule pinned as `quota-score@2`, the **one** implementation of a pool's headroom and its order (T185). `accountQuotaOf` reads each window of an account's pools (known only when its reading is at most `staleReadingSeconds` old, `ok`, with a used share, and its reset still ahead; its headroom above `reservePercent`; its reset; whether it is over the reserve), the binding window, the soonest reset, and whether the account is free by its quota, with why not; an unknown, stale, or `unknown: available`-only window is never headroom (INV-2). `headroomOrderOf` keys accounts in the use-it-or-lose-it order: over the reserve last while another is free, known before unknown, the window that resets soonest with headroom first, the most headroom. `quotaScoreOf` puts the reserve key first, then tier, quota class (metered last, never free), the rest of that order, load, priority, and id, and chooses the first free one, every candidate with why. The dispatch pass, routing's order (every route), and the capacity summary all call these; none computes headroom itself. `QUOTA_DEFAULTS` (a 20 % reserve, D63) and `QUOTA_RANGES` are the resources row's `quota` |
| `DESCRIPTION`, `MAX_DESCRIPTION` | a Worker's configured `description` (`capability-descriptor@1.7`): plain text on one line, 1 to 200 characters, no control character; the one rule of the configuration rows that define Workers (agent-workers `workers[]` and `roles[]`, models `models[]`, accounts `accounts[]`), shown by the [roster](../../docs/design/roster.md) |
| `brierScores`, `ADVICE_QUESTIONS`, `ADVICE_EVENT`, `ADVICE_OUTCOME_EVENT`, `ADVICE_SHADOW_ATTEMPTS` | the dispatch advisor's calibration ([PROP-0015](../../docs/proposals/0015-right-worker-right-job.md) J1, [design](../../docs/design/workflow-engine.md#the-dispatch-advisor-in-shadow)): its three questions per candidate, the events a choice's advice and a dispatched attempt's outcome are recorded in, D74's 100 attempts, and the Brier score of each question beside always answering the observed rate; the workflow engine records them, the report scores them |
| `sqliteRuntimeProblem`, `nodeVersionProblem`, `SUPPORTED_NODE` | the supported Node runtime ([CON-2](../../docs/requirements/constraints.md)): the version range, then a NUL round trip through `node:sqlite`; the store and `system init` / `start` refuse a runtime that fails either |

- **Conformance runner** ([`conformance/runner.ts`](conformance/runner.ts), test-only, never
  shipped): runs the conformance suites of seams defined since ADR-0037
  ([seam definitions and conformance](../../docs/architecture/plugin-model.md#seam-definitions-and-conformance)).
- **Depends on:** `@tsuuanmi/system-schemas`, `ajv` and `ajv-formats`, the system `git` binary for subjects and repository snapshots, and DSH's `@deepseek-ai/dsh-home-paths` (a path library with no runtime; its declared Cordis peer is satisfied by the workspace).
