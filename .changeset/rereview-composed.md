A remediation cycle's re-review is given the instructions its review was given, never the review's template text as it is:
- The re-review is worded as the review the cycle started from: that review's prompt, composed again at promotion. `{{input}}` is the caller's text, and each `{{node:<id>}}` points at the result that review read, except the step that wrote the change, whose place the fix that wrote the new subject takes (its pointer's note names the fix). A re-review of a plan step's review stays the step's model text, used as it is. Before, the re-review sent the template's placeholders raw (seen with `agent-review`'s review).
- No Worker execution starts with a template's placeholder unfilled. A template whose text holds a `{{` the engine does not fill (an unknown name such as `{{inptu}}`, a different spelling such as `{{ input }}`, no closing `}}`, or `{{team}}` outside a team's ballot) is refused at load, alone, with why, as `system check` reports it; the README already allowed only `{{input}}`, `{{node:<id>}}` of a dependency, and `{{grown}}`. A step whose stored template holds a placeholder the engine cannot fill fails before anything is routed or sent, as `config_error`, on a `gate` decision `workflow.instructions` naming it; so does a step an earlier version promoted with a re-review's placeholders stored unfilled, and `system continue` composes it again. Text the engine never expands (the caller's input, a dependency's result, a plan step's model text, a fix's quoted findings, a diff) is data, and is sent as it is.
