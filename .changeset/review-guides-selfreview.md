REVIEW.md per area, and the author's fresh-context self-review instead of the near-empty validate step (T267, D93):
- **Review guides.** A review step's brief points at the `docs/review/*.REVIEW.md` guides of the areas its change touches, and only those (every guide when the change's paths could not all be read), as a `review-guides@1.0` report that records each guide's file, version, and hash. A guide has front matter (`paths`, `owner`, `version`) and six sections (what failure looks like here, what to check first, paths to skip, nit cap, evidence rule, summary rule); it is read from the repository the run's worktree was cut from, never from the worktree under review. The first six are written for the workflow engine, agent Workers and confinement, the gate and approvals, the board and dispatch, the web UI, and the docs ([the handbook](../docs/design/handbook.md#review-guides-reviewmd)).
- **The author verifies before review.** `algorithm-development`'s `develop:1` ends with its Worker appending the output of the required checks to the task's dossier as an `evidence` entry (`dossier_append` now takes `evidence` from a writing step; its author is the Worker). A step that ends without one, or with one that shows no exit code and output for each command check the criteria name, is refused (`evidence_missing`, a `workflow.evidence` gate decision); a template node says it with `showsEvidence`. **Behaviour change:** such a step requires the new `dossier` capability, which an agent Worker offers when its runtime gives host tools, so a Worker that could not write the entry is never admitted to it; every fix grown from it must show the checks' output again.
- **Fresh-context self-review.** A new `selfreview:1` step (`selfReview` on a template node) is a review of the exact change in a new session on the author's account, never seeing the author's transcript, and given only the goal, the diff, and the review guides (no dossier, no task pointers, no files; `dossier_read` is refused). **Behaviour change:** an agent Worker's run in a worktree of its own now finds in `.system/` only its own brief's files: one an earlier step's brief placed (the dossier, the board) is removed before its agent starts; its important findings are verified as a review's are (ADR-0075), and the confirmed ones grow a fix in the author's session, answered and re-reviewed before `review:1` starts, with no approval gate. It counts for no risk tier, provider family, or acceptance. **Behaviour change:** it runs on a Worker of the author's account that proves `review` (its read-only role) and is given no kinds; with none, it fails admission with nothing sent.
- **The validate step is removed** (template version 2: it measured a median of 0.4 minutes and caught nothing the run's required checks at acceptance did not). `review:1` is the final step, so the run's result is its review. **Behaviour change:** a `kinds.validate` key of the row's configuration is accepted and ignored; remove it, and any Worker given only `validation` takes no step of this template.
