Workers read their workspace through System's own read-only MCP server instead of a shell (T200b, follow-up of T198, per research T204). Since T198 every `Bash` call is a `command` under both runtimes, so a Codex Worker, which has no file-reading tool of its own, could read only through commands the operator approved, and reviews and validations stalled.
- agent-runtime-core: the workspace reads server (`src/workspace-reads.ts`, Node built-ins only, no third-party server): MCP over stdio with three read-only tools bound to one workspace fixed at start: `read_file` (a line range, bounded bytes), `list_dir` (bounded entries), `search` (a fixed string or a regular expression, bounded matches, files, line and pattern length, and time, in a worker thread ended at its deadline; no shell). Every path is resolved with `realpath` and must stay inside the workspace (`..`, an absolute path outside, and a symlink out are refused); git's data and secret-named files (`.env`, keys, credentials) are never read; each open is checked again through `/proc/self/fd`; MCP Roots are ignored. Every bound is a validated argument (`WORKSPACE_READ_BOUNDS`). New `RuntimeEvidence.workspaceReads` and `RunSpec.workspaceReads`.
- Codex runtime: every run, the read-only sandbox's included, registers the server (`mcp_servers.workspace`, a per-run override; the operator's own MCP servers stay refused), started as `node` under a bubblewrap of its own inside the run's confinement, the host and the workspace read-only, no network. The probe proves it starts there before it reports `workspaceReads`; otherwise no Codex Worker is admitted. Claude Code keeps its own Read, Grep, and Glob.
- agent-workers: for a run whose runtime reports `workspaceReads` (its evidence, threaded to the gate as `cleanShells` is), the gate classifies exactly `mcp__workspace__read_file`, `mcp__workspace__list_dir`, and `mcp__workspace__search` as `read` (inside the workspace, no `..`, not git's data) and refuses any other tool of that server (`unclassified-tool`); under a runtime that reports no such server every `mcp__workspace__…` tool is refused. Its new refusals reuse the T207 reason codes (`outside-workspace`, `git-data`, `unclassified-tool`). `Bash cat` stays a `command`. The Worker's Tools section (T207) of a runtime that gives the server names its tools as the reading tools and tells the Worker to read with them, never with a shell. New config `workspaceReads` (the server's bounds, each within its range, checked at load; left out of a migrated row at their defaults).
