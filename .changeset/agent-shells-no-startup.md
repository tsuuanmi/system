The tool gate takes a shell command for a read only for a runtime that enforces shells without startup code, and neither Codex nor Claude Code does (T198, from the review T197 and T190's report). Until now the gate read `echo`, `pwd`, `true`, `false` (T187) and `cat`, `head`, `tail`, `wc`, `ls`, `stat`, `file`, `sed -n`, `rg`, `grep`, `find` on absolute paths inside the workspace (T147) as reads, trusting that each word runs the program it names. A function or an alias called `echo` or `cat` in a shell's startup files (`~/.bashrc`, `~/.bash_profile`, a `BASH_ENV` or `ENV` file, an exported function), or a shell the call picked itself, would have run instead.
- agent-runtime-core: new `RuntimeEvidence.cleanShells`, which a runtime reports only when it itself starts every call's shell non-login and non-interactive, with no startup file or startup variable (`bash --norc --noprofile`, no `BASH_ENV` or `ENV`), in a shell the agent cannot choose. `childEnvironment` drops every variable a shell runs code from (`SHELL_STARTUP_VARIABLES`: `BASH_ENV`, `ENV`, `ZDOTDIR`, `PROMPT_COMMAND`, `PS0`, `PS4`, `SHELLOPTS`, `BASHOPTS`, `INPUTRC`, and exported `BASH_FUNC_*` functions), whether it comes from the daemon's environment, a forwarded name, or an explicit value. New: `agentHome` (a fresh, empty, owner-only home outside the workspace, bound back read-only, removed with the run), `agentShellEnvironment` (`HOME` set to that home, no startup variable, and none that moves a shell's startup files: `SHELL_CONFIG_DIRECTORIES`, `XDG_CONFIG_HOME` and `XDG_CONFIG_DIRS`), and a regression under the real confinement: a function named `echo` and `cat` planted by a tool call in every startup file it can reach never runs on a later call, plain, login, or interactive.
- Claude Code and Codex runtimes: no startup code the agent writes ever runs before a command, whatever shell and login mode a call runs in. Each run's `HOME` is a fresh private directory in the run directory (`<DSH_HOME>/system/run`, the new `runDir` option for Claude Code), outside the worktree and bound back into the confinement **read-only**, so it stays empty and no call can write a startup file there. Codex refuses a `shell_environment_policy.set` that names a startup variable, `HOME`, or an XDG configuration directory. Claude Code's command sandbox denies writes to its home, which holds the shell snapshot it sources, and to the shells' `HOME` (`commandSandbox(workspace, startup)`, `filesystem.denyWrite`). Neither reports `cleanShells`: Codex lets each call pick its shell program and login mode, which its hook does not show, and Claude Code starts its shells its own way.
- agent-workers: the gate classifies a `Bash` probe or inspection command as `read` only for a run whose runtime reports `cleanShells`. Under every runtime today, each such call is the `command` it is, judged by its exact argv.
- web-ui: a start System proposes says, in its Deny button's accessible description (*does not start it, and this attempt is not asked again*, on its card too) and in a short note under the buttons, that Deny is final for that attempt (T197).
