A Worker's own tool call can run the browser tests, and a sandbox's placeholders never count as changes (T265; on T256 a develop step's own vitest found no usable Chrome, skipped 58 browser tests, and `test:affected` ran the whole suite for the sandbox's dotfiles). A writing run's command sandbox, the runtime's second layer inside the read confinement, now gets what a check's confinement gives a browser test (`toolSandboxAllowances`): the managed Chrome readable (Claude Code `allowRead`, the directory `SYSTEM_BROWSERS_DIR` names), the confinement's private `/dev/shm` writable, and the run's report file writable; Codex gets the same as `sandbox_workspace_write.writable_roots`, after the operator's own. Claude Code's sandbox also refuses every unix socket on Linux, which Chrome needs: the runtime's new `unixSockets` option (default on) sets `allowAllUnixSockets` for a writing run, and only after that run's confinement masks every unix socket of the host the account could connect to (`writableUnixSockets`: every socket the host has bound, from `/proc/net/unix`, and every one on disk under `/run`, `/var/run`, the home, container engines' own directories, and every path the confinement binds back, by what the run's child sees; a container daemon's, the system bus), each under the null device after every other mount (the confinement's new `masks`), and with the directories where the host's daemons make their sockets (`socketDirectories`: `/run`, `/var/run`, the container engines' directories) denied to its commands for the whole run (`denyRead`), those in the home also hidden from the run's own confinement and made first, empty and owner-only, when missing, so a socket a daemon makes there after the run started, in a directory that did not exist before or not, is not reachable either; where the host's bubblewrap cannot mount over a socket (bubblewrap 0.4), each such socket's own directory is hidden instead (`socketCovers`), unless that would hide the home, a directory above it, or a path the run binds back; a list it cannot read, a scan that reaches its bound, or a host whose bubblewrap starts the command sandbox neither way leaves them refused for that run, which runs as before; `false` refuses them always.

Each `workspace-write` run gets a fresh owner-only report file outside its worktree (`RunSpec.reportFile`), bound into its confinement and named in `SYSTEM_CHECK_REPORT_PATH`, as a check's is. When its own test runs skipped browser tests, the result says so (`agent-result@1.5`, new optional `notRun`: `its browser tests (<why>)`), and the review of the change is told before its subject; a report file that could not be made or read is said too (`reportUnread`), and the review told that whether its browser tests ran is not known.

Claude Code's sandbox mounts empty placeholders for the files it denies writes to in the directory its commands start in (`.bashrc`, `.profile`, `.gitconfig`, `.mcp.json`, `.idea`, `.vscode`, `.claude/settings.json`, …). An untracked one at those paths that holds nothing is left out of a run's subject and diff and of `test:affected`'s changed files (`SANDBOX_PLACEHOLDERS`, `sandboxPlaceholder` in libs), and removed before a landing commits; one with content still counts.
