A project from a template by kind, `system project new` (PROP-0016 I5 part 0, D87, D88):
- `system project new --kind software-repository --id <id> --repository <path> [--target-branch <b>] [--coordination <dir>] [--dry-run]` renders the template shipped in `packages/cli/templates/software-repository`. It holds a charter draft (objective, scope, non-goals, done-when, budget lines), the writing role and the repository's worktree setup (an offline setup and checks per toolchain, chosen by lockfile: pnpm, npm, cargo, uv), the commands they need as a policy change, auto-accept off, an empty lessons file with T220's bounds, and the lead's onboarding (`LEAD.md`, pointing at the lead's playbook).
- It refuses an unknown kind, a repository that is not a git checkout's top level, a detached HEAD or a `--target-branch` other than the checked-out branch (a landing merges into the checked-out branch), an id in use (its coordination directory, the board, or the policy set has it), and anything it renders that does not validate against `mcp-board@1`, `autonomy-policy@1`, and the approval queue's and `agent-workers`' own load-time checks.
- It writes only the project's coordination directory (`LEAD.md`, `lessons.md`, `decisions.md`, `charter.json`, `policy-change.json`, `profile-patch.yml`, and `requests.json`, the ledger of what was filed, a new `project-requests@1.0` record validated on every write and read), files the charter and one policy change on the approval queue, and prints the profile patch fragment, which it never applies. A creation that stopped part-way is completed by running the same command again: it files only the outstanding requests. Every write and request is listed; `--dry-run` prints all of it and writes and asks nothing.
