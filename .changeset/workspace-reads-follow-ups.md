Workspace reads server follow-ups from the security review of T200b (T213):
- `list_dir` and `search` read a directory one entry at a time (`opendir`) and no further than 10 x `maxEntries` entries; `list_dir` then says "at least N entries" and where it stopped, and `search` how many directories it read only so far.
- A search's worker thread runs with `resourceLimits` derived from `maxScanBytes` (new `searchResourceLimits`: an old generation of 64 MiB and 4 x `maxScanBytes`, a young one between 16 and 64 MiB). It holds one line of a file at a time, not an array of all of them. The thread reports its heap limit, and an answer from a thread bounded more loosely is not used. A thread out of memory is a refusal.
- More secret names (`SECRET_NAMES`): `.envrc`, `secrets.env`, `.secrets/`, `.pgpass`, `*.tfvars`, `*.tfstate`, `kubeconfig`. New `SECRET_PATHS` (`.kube/config`, `.docker/config.json`, `.aws/config`, `.aws/credentials`). A bare repository named `*.git` counts as git's data. A file or directory the workspace's own `.gitignore` files or `.git/info/exclude` ignore, and whose path holds a secret's word in any segment (new `SECRET_LIKE`: secret, token, password, credential, private, API key), is refused and left out, checked on the whole path (an ignored `private/config.txt` is refused though `private/` is not ignored), as written and as resolved (an ignored `deploy-token.txt` symlink to an ordinary file is refused). Bracket sets are parsed as git's wildmatch does, POSIX classes such as `[[:digit:]]` included; a class it does not know fails closed. The server reads the ignore files itself and runs no git. It matches their patterns with an automaton in bounded time, not with backtracking regular expressions. An ignore file over 256 KiB, or a call past its matching budget, counts as ignoring every such name (fail closed). The remaining gap is documented: these are names, not contents, and git's global excludes are not read.
- A regular file with more than one hard link is refused and skipped by a search, except under `node_modules`, where pnpm links its store. Before, a hard link to `.env`, or to a file outside the workspace on the same filesystem, was read under another name.
- Stdio: a line that is not JSON counts toward the 32 lines waiting and is refused past them, and a whole line over 1 MiB that arrives in one chunk is refused like one that arrives in parts. The docs say that, served one at a time, a call queued behind a long search can exceed Codex's tool timeout.
