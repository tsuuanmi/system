A Worker can run the web UI's browser tests in its own confinement (T247; T239 could not, and three review rounds failed on it). The confinement binds the managed Chrome (`$DSH_HOME/system/browsers`) back read-only by default, beside the agent CLIs (agent-runtimes `readOnly`; a profile that sets `readOnly` itself must list it), and names where inside in `SYSTEM_BROWSERS_DIR` (a confinement's new optional `env`, non-secret values `confinedCommand` sets with `--setenv`), so a custom `DSH_HOME`, which a child's environment never carries, still finds it; the tests find it there, and the developer cache `~/.cache/system-chrome`, in the account's own home when `HOME` is the Worker's private one, and need only Chrome, not Xvfb, for their headless runs. Chrome starts without its own sandbox there (Patchright's `--no-sandbox`): the confinement isolates it, with no network in a check; `/dev/shm` is its private tmpfs; and the tests give it its own XDG directories in the private `/tmp`, since under a read-only `HOME` its crash handler exits (`--database is required`) and Chrome with it. The headed suites keep their own Chrome lookup and gate as before.

Where no Chrome can run (none found, or one that does not start there, decided by starting it once), a browser test is skipped with the note `browser tests did not run: <why>`, and the suite's last line says how many and why. In a run's check the suite appends `browser-tests-not-run: <detail>` to the check's report file: the check keeps its outcome, its reason and answer (`notRun`) say what did not run, and the acceptance's reasons tell the review that the pass says nothing of those tests. A report file the suite cannot write fails the run, loudly.

A check's report channel is now a file, not the descriptor `SYSTEM_CHECK_REPORT_FD` (which never reached a suite through pnpm's lifecycle runner, and a pipe's `/proc/<pid>/fd` name cannot be reopened): a fresh owner-only file in the check's private directory, bound writable at its own path (written, never replaced, inside), named in `SYSTEM_CHECK_REPORT_PATH`, and read once the command ended; one that cannot be read makes the check an `error`. A suite that reported `nested-confinement-refused` on the descriptor writes the same line to that file instead (ADR-0063, amended). A repository whose checks run vitest names `node_modules/.vite-temp` (vite's bundled configuration) in `checkScratch` beside `node_modules/.vite`. The test runner's stale sweep leaves a parent it cannot remove (a nested confinement's mount points) instead of failing the run.
