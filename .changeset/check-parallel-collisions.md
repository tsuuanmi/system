`pnpm check` now refuses what parallel changes collide on (T210), as seen landing parallel runs on `dev` on 2026-10-26. `check:docs` fails on two ADRs or two proposals with one number. A new `check:migrations` reads every plugin's store migration list from the source with the TypeScript parser, imported migration constants included, and fails on a version declared twice or versions not strictly increasing in list order (on an install that ran the first, a second migration with the same version never runs), and on a list it cannot read statically. `check:schemas` compares every schema with a committed contract snapshot (`scripts/schema-snapshot.json`, refreshed by `pnpm gen:reference`): a property required, no longer required, or removed, or an existing subschema narrowed or relaxed, fails unless the schema carries a newer version note. Regenerating keeps a schema's old entry while it is changed in place, so it cannot hide the change. A new `CONTRIBUTING.md` tells a writer, person or Worker, to take the next free ADR number, migration version, and schema version.
