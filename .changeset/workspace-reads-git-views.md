Workers read git history without a shell (T223, follow-up of T222): the workspace reads server gains four read-only git views of the run's worktree.
- agent-runtime-core: `git_log` (at most `count` commits, within `maxLogCount`; `skip`; from a commit's hex id; `paths`; a fixed set of `fields`), `git_show` (one commit by hex id: its header and message, its stat and/or patch, `paths`), `git_diff` (the worktree or the index against HEAD, or two commits by hex id; a patch or its stat; `paths`), `git_status` (porcelain v1 with the branch line). Git runs with an argv the server builds, never a shell: commits only as hex ids (`COMMIT_ID`), paths through the same `realpath` checks as `read_file` (one only history has included), then after `--` as literal pathspecs. Every setting that could run a program on a read command is off (`GIT_CONFIG_PINS`: `core.fsmonitor=`, `core.pager=cat`, `core.hooksPath=/dev/null`, `diff.external=`, `core.attributesFile=/dev/null`, `log.showSignature=false`, `protocol.allow=never`, the submodule settings; `--no-pager`, `--no-optional-locks`, `--no-ext-diff`, `--no-textconv`, `--no-show-signature`, `--ignore-submodules=all`), and so is every filter driver the repository's configuration names, since a clean filter runs on `status` and a worktree `diff`, not only on checkout. Its environment is its own (`gitEnvironment`: `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_LAZY_FETCH=1`, the repository only at the workspace's root). Files named as secrets are left out of every stat, patch, and status. New bounds `maxLogCount`, `maxGitBytes`, `gitTimeoutMs` (validated ranges, INV-9).
- agent-workers: the gate classifies exactly the four views as `read` (`mcp__workspace__git_log`, `…git_show`, `…git_diff`, `…git_status`), only for a run whose runtime gives the server, when every commit is a hex id and every path is inside the workspace and not git's data; they count among the agent's reading tools (T222), and the Worker's Tools section names them. The `workspaceReads` config takes the new bounds.
- Codex runtime: the server's tool timeout is the longer of the search and git deadlines, and 30 s.
