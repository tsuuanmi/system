# Glossary

Short definitions of the terms the documents use. Each links to the document that owns the
term; that document is canonical. Plugin-model vocabulary (plugin, service, seam, library,
bundle) is in the [plugin model](../architecture/plugin-model.md#vocabulary).

| Term | Meaning |
|---|---|
| **Approval request** | One action that waits for the operator, on one exact subject, with an expiry that denies it: the one entry of the approval queue. Only the operator's verdict approves it, and only for that subject ([approvals](../design/approvals.md#a-request)). |
| **Autonomy policy** | The operator's configuration of what runs unasked: a mode (`auto`, `notify`, `ask`, `forbid`) per action class, the checks a result must pass, and how long a request waits. Code applies it, never a model ([approvals](../design/approvals.md#the-autonomy-policy)). |
| **Ballot** | A team member's sealed vote over every option: one choice, a ranking, a rationale, the strongest point of each option it did not choose, its open objections, and a confidence. No member sees another's ballot until every ballot is in ([teams](../design/teams.md#ballots)). |
| **Barrier** | A mailbox gate on a session group: messages are stored but not delivered until it opens ([sessions](../design/sessions-and-messaging.md#direct-messaging)). |
| **Board task** | A unit of work that outlives a run, in a project with an approved charter. The workflow engine serves each attempt as one run; the board moves the task, and only an accepting decision on its exact result makes it done ([board](../design/board.md#task)). |
| **Capability** | A named semantic, never a tool name, that a Worker must prove with current evidence before routing admits it, such as `reason`, `deep-research`, `develop`, or `review` ([capability vocabulary](../design/routing.md#capability-vocabulary)). |
| **Confirmed finding** | A review finding whose quote matches a line its members were shown, exactly after trimming both ends, on the cited line or within two lines of it. The check is deterministic, never a model's. A confirmed blocking finding decides a review `changes` ([quote checks](../design/teams.md#quote-checks)). |
| **Decision artifact** | An immutable record of one decision (admission, route, tier, egress, acceptance, gate, recovery, …) with every candidate and why it was or was not chosen, written before its effect commits ([artifacts](../design/artifacts.md#decision-artifacts), [INV-13](../architecture/invariants.md#inv-13-every-decision-is-an-artifact)). |
| **Feature** | A website feature that one account may or may not offer, such as Deep research or Web search. It becomes a routing capability of that account's Workers only after the account's feature probe proves it (`system account probe`; [driver interface](../design/provider-turns.md#driver-interface)). |
| **Lease** | A time-bounded, token-holding claim on a resource with a monotonic generation. Every commit fences on the exact lease inside its transaction, so a stale holder cannot commit ([scheduling and leases](../design/scheduling-and-leases.md#lease-generations)). |
| **Option** | What a team votes on, fixed once every member has proposed: in a `brainstorm`, each member's recommendation, verbatim (`O<k>`); in a `review`, `pass` or `changes` ([teams](../design/teams.md#options)). |
| **Preset** | A named bundle layer, shipped in the system bundle, that `system init --preset <name>` composes right after it, such as `api-first`, which turns off every row that drives a website ([ADR-0025](../decisions/adr/0025-api-first-composition.md)). |
| **Profile** | Two meanings. A **DSH profile** is the composition of bundles and the operator's patch that `system start` boots ([plugin model](../architecture/plugin-model.md#vocabulary)). A **domain profile** is a plugin, such as `profile-scientific-research`, that contributes workflow templates through `ctx.workflow.template` ([workflow templates](workflow-templates.md#profile-templates)). |
| **Provider family** | An opaque string on a Worker's capability descriptor for who ultimately serves its work: a website account's provider, an agent runtime, or a model catalog entry's `family` (default its route). Routing only compares families for inequality, to keep a step such as a second literature review off the family of another step, and never names or ranks one ([provider diversity](../design/routing.md#provider-diversity)). |
| **Quota class** | What a Worker spends: `subscription-chat` (website accounts), `agent-plan` (Claude Code and Codex plans), `metered` (API models), or `local` (models on this machine). Routing prefers them in the configured order ([quota and cost policy](../design/routing.md#quota-and-cost-policy)). |
| **Receipt** | A provider turn receipt, persisted immediately before a prompt is sent. It binds the account, conversation, request, and prompt and response hashes, so a restart reconciles the turn instead of resending it ([turn receipt](../design/provider-turns.md#turn-receipt)). |
| **Resource pool** | A configured source of Worker capacity, such as a plan's window or an API key, with the latest reading of each limit window and the usage counted against it ([resources](../design/resources.md#pools-and-availability)). |
| **SessionId** | The durable identity of one Worker session: a Worker's participation across turns and restarts, with its own mailbox. The native conversation handle behind it may change; the `SessionId` does not ([sessions](../design/sessions-and-messaging.md#concepts)). |
| **Source snapshot** | What a review's members read, recorded as an `evidence` artifact (`source-snapshot@1.0`): a public repository's files at one pinned commit, or the caller's text as the one file `material`, line-numbered, with every file not read and why ([sources](../design/teams.md#sources)). |
| **Tally** | A team's deterministic count of one round's ballots against a strict majority of every member, recorded as a `vote` decision. On a split with an objection open and debate rounds left, it appends a debate and the next tally ([teams](../design/teams.md#tally-and-debate)). |
| **Template** | A named list of workflow nodes, each with capabilities, a minimum tier, a conversation mode, and an acceptance contract. Built in, contributed by a domain profile, or configured ([workflow templates](workflow-templates.md)). |
| **Tie** | A team vote with no strict majority after its last tally. The run blocks until the caller (or the operator) casts the deciding `vote`, or until `tieTimeoutHours` pass and the team ends inconclusive ([teams](../design/teams.md#tie)). |
| **Tier** | The intelligence level a Worker configuration declares: `economy`, `standard`, or `frontier`. A node's tier is a minimum; routing picks the lowest admitted tier at or above it ([intelligence tiers](../design/routing.md#intelligence-tiers)). |
| **Variant** | A named set of field values (capabilities, tier, conversation, acceptance, prompt, objective) a template node declares; the caller picks one at start, such as `research`'s `deep` ([variants](../design/workflow-engine.md#variants)). |
| **Worker** | An opaque assignable executable unit with proven current capabilities: a website account at one tier, a configured agent runtime, or a model catalog entry. Routing admits Workers by capability, never by name ([components](../architecture/components.md#capabilities)). |
| **Worker source** | A plugin that describes its Workers to `ctx.workers` and runs work on them: `turns` for website Workers, `agent-workers` for agent-runtime Workers, and `models` for model Workers ([routing](../design/routing.md), [components](../architecture/components.md#capabilities)). |
| **Worktree** | A git worktree of an agent Worker's repository, one per workflow run, on the branch `system/run/<runId>`, where that run's agent runs work ([agent Workers](../../packages/plugins/agent-workers/README.md)). |
